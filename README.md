# AI Infra Platform · Web Console

把调度决策变成可见证据的控制台。

## 为什么需要这一层

调度器每次选了一个后端。如果这个选择只留下一行日志，那它既不可验证、也讲不清楚。

这一层只做一件事：**让一次请求的路由过程在屏幕上可解释。**

- 这个请求为什么走了这个后端
- 当时其他候选的评分分别是多少
- 从进来到吐第一个字，每一跳花了多少时间

它存在的理由是让"调度"这件事从抽象算法变成看得见的东西。这是它全部的价值，也是它唯一的目标。

## 它不做什么

- **不做业务逻辑**，**不直连数据库**
- **不绕过接入层**去直连后端服务
- **不做深度运维图表**。那是 Grafana 的职责，重复造只会两边都不好用

## 两条边界原则

**前端的校验是体验，后端的校验是安全。**
前端可以提示"这个字段格式不对"，但后端必须独立再校验一遍。任何"前端已经验过了"的假设都是漏洞。

**前端的任何状态都是可以丢的。**
刷新页面、关掉标签、断网重连，都不应该影响服务端状态。前端持有的只是它自己的视图。

## 目录

```
src/
  pages/        页面级组件
  features/     按业务能力组织的组件与状态
  api/          接口客户端。所有请求的唯一出口
  shared/       通用组件与工具
```

**所有网络请求必须经过 `api/`**。组件里出现裸请求，视为设计错误。

## 与其它仓库的关系

| 仓库 | 关系 |
|------|------|
| `ai-infra-platform-api` | 唯一的数据来源 |
| `ai-infra-platform-db` | 无直接关系。前端不得接触数据库 |
